# 架构

> 状态：Phase 2a 已实现数据层、导入、发票级导出、报销行与报销单 Excel；
> Phase 2b 工作台 MVP 已实现 pywebview 窗口、本地 Vue UI 与 `app/api.py` 桥接；
> 规则学习与仪表盘仍未做，不提前写不存在的细节。

## 目标形态

单机桌面应用。Python 负责解析、存储、导出；本地 Web UI 负责交互；两者通过 pywebview 的 JS bridge 通信。全程离线。

```
┌──────────────────────────────────────────────┐
│  本地 Web UI（Vue 3 + Tabulator + ECharts）   │
│  批次 / 发票池 / 报销单 / 汇总 / 导出         │
└───────────────────┬──────────────────────────┘
                    │ pywebview JS API (JSON)
┌───────────────────▼──────────────────────────┐
│  app/api.py — 受控的桥接层                    │
│  只暴露用例方法，不暴露文件系统/数据库细节     │
└───────────────────┬──────────────────────────┘
┌───────────────────▼──────────────────────────┐
│  app/core/                                   │
│  parser/  票型识别、字段提取、置信度          │
│  db/      SQLite、迁移、查询                  │
│  import/  扫描、拆分、去重、缩略图            │
│  export/  Excel、合并 PDF、ZIP                │
│  reports/ 报销行、里程、发票关联、报销单导出  │
│  rules/   分类规则、学习（Phase 2b）          │
└───────────────────┬──────────────────────────┘
                    │
        ┌───────────┴───────────┐
        │ SQLite（应用数据目录） │
        │ 源 PDF（只读引用）     │
        │ 导出目录（用户选择）   │
        └───────────────────────┘
```

## 数据流

1. 用户选择文件夹/文件 → 扫描 PDF 与图片。
2. 计算哈希，跳过已导入文件；多页 PDF 按票号或页拆成发票记录。
3. 解析器按票型提取字段，给出每字段置信度。
4. 写入 SQLite；低置信度/重复/可疑金额进入“待确认”队列。
5. 用户在发票池修正；修正可沉淀为分类规则。
6. 用户从发票池生成报销行（`from-invoices`），或手动新增无票/里程行；一行可关联多张发票。
7. 导出：发票证据包（明细 Excel + 分类/公司汇总 + A4 二合一 PDF）与
   《费用报销支出明细表》Excel；两种导出都走同一路径守卫与临时文件替换；源目录只读。
   界面勾选与规则学习随 Phase 2b。

## 数据模型（已实现 + 计划）

已实现（`app/core/db.py`，schema 版本 2）：

- `batches`：批次（`created_at`、`label`、`source_dir`）。
- `files`：源文件（SHA-256 主键、批次、路径、页数、入库/重复条数、导入时间）。
- `invoices`：发票记录（票号、日期、买卖双方、金额/税额整数分、类别、置信度 JSON、
  warnings JSON、`needs_review`、来源文件与页）。票号建索引但不做全局唯一；
  同号但身份字段不一致时双保留并互相标记冲突（ADR-009）。
- `reports`：报销单表头（公司、部门、报销人、月份、标题）。
- `report_lines`：报销行（日期、费用名称、金额整数分、有票标记/附注、项目、来源
  manual/invoice/mileage、里程 km；金额为准，km 仅元数据）。
- `report_line_invoices`：报销行 ↔ 发票多对多（ADR-011）。

计划：

- `invoice_items`：发票明细行（项目、规格、数量、金额、税率）。
- `rules`：关键词/销售方 → 类别（Phase 2b）。
- `settings`：默认公司、报销人、导出目录、里程单价。

## 数据库边界

- 默认位置 `data/invoicedesk.db`；`data/` 内独立 `.gitignore` + 全局 `*.db` 忽略兜底。
- `db.connect` 默认拒绝仓库内非 `data/`、`out/`、`tests/local/` 的路径，以及 UNC、网络盘、OneDrive 等非本机存储；CLI `--force` 是显式例外。
- 金额只以整数分落库，避免 REAL 浮点漂移；Python 侧仍用 `Decimal`。
- 导入去重：文件 SHA-256 命中则整份跳过；票号命中则跳过该条；无票号记录保留待确认。

## 关键边界

- 源文件只读；任何重命名/整理都是“另存副本”，并需用户明确触发。
- 数据库放应用数据目录，支持便携模式；自动备份/恢复随 Phase 3。
- 解析器不依赖网络；AI 审查流水线只看代码，不看数据。
- Excel 导出基于内置模板，格式与现有报销单一致；不直接改用户的原始 xlsx。

## UI 结构（Phase 2b 已实现部分）

- `app/main.py` 创建 pywebview 窗口，加载 `app/ui/index.html`；
  `app/ui/app.js`（Vue 3.5 本地内置，无 Node 构建）只通过 `app/api.py` 读写数据，
  不接触文件系统与数据库句柄。
- 顶部栏：导入发票、导出证据包、新建报销单。
- 左侧发票池：批次/日期/搜索/仅未关联/含待确认筛选，勾选发票；点击行打开右侧票面抽屉。
- 右侧报销单：切换/新建/编辑表头，行内编辑日期、费用名称、金额、有票/附注、项目、备注；
  从所选发票生成行、里程行、关联/取消关联、导出报销单；发票池可隐藏以专注编辑报销单。
- 右侧抽屉：PyMuPDF 渲染当前页为 PNG data URL + 发票字段/置信度/警告 + 快速关联。
- 弹窗：新建/编辑报销单表头、里程计算器、导入文件夹（粘贴路径）。
- 系统深色模式随 `prefers-color-scheme` 自动切换；手动开关与仪表盘未做。

## 桥接层（`app/api.py`）

- 每个公开方法返回 `{"ok": true, "data": ...}` 或 `{"ok": false, "error": "中文提示"}`，
  异常不穿透到 JS；每次调用新建并关闭一个 SQLite 连接，避免 pywebview 多线程共享连接。
- 写操作复用 `app/core/reports.py` 的业务校验；输出路径沿用 `paths.output_path_reason`；
  导出仍先写临时文件再替换，符号链接目标拒绝写入。
- 票面预览只读源 PDF，按 (invoice_id, zoom) 做最多 8 条的内存缓存，不落盘。
- 导入接受用户粘贴的文件夹路径：pywebview 的文件对话框要求 GUI 线程，桥接线程无法安全调用。
- 页面带 CSP：`default-src 'none'`，仅本地脚本/样式与 `data:` 预览图，`connect-src 'none'`；
  Vue 的 in-DOM 模板编译需要 `unsafe-eval`。桥接调用用一把可重入锁串行化，避免并发写。
