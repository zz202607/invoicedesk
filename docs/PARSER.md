# 解析引擎设计

> 状态：**Phase 1a 已实现**（2026-10-28）。实现以 `app/core/parser.py` 为准；任何规则都要有 fixture 支撑。

## 为什么不能用旧办法

旧脚本按 `text.find()` / 正则顺序取第一个匹配。老版增值税电子票的文本是乱序的：标签在一块，值在另一块；金额区同时出现不含税金额、税额、价税合计。顺序正则必然取错或取空。

## 核心算法

1. 用 PyMuPDF 取每个词的文本 + 坐标（`page.get_text("words")`）。
2. 识别票型（版式特征 + 关键字），交给对应 parser。
3. 每个字段用**锚点 + 空间最近值**：
   - 锚点：`发票号码`、`开票日期`、`价税合计`、`（小写）`、`销售方`、`购买方`、`项目名称`
   - 在锚点右侧/下方一定范围内找候选值，按距离、字体、数字形态排序。
4. 金额三重校验：
   - 小写金额
   - 大写金额（壹佰……）转数字
   - 不含税金额 + 税额
   - 三者一致 → 高置信度；不一致 → 标记待确认，不静默取最大数。
5. 日期：优先 `开票日期` 锚点；铁路票单独取乘车日期与开票日期，不混用。
6. 每个字段输出 `value + confidence + source`（页面坐标/锚点）。

## 票型

| 票型 | 识别特征 | 特殊处理 |
|---|---|---|
| 全电普通发票 | `电子发票（普通发票）` | 20 位票号；小写金额常与标签分离 |
| 全电专用发票 | `电子发票（专用发票）` | 同普票，税额校验更严格 |
| 老版增值税电子普票 | `增值税电子普通发票` | 文本乱序；金额必须三重校验 |
| 通行费发票 | `通行费` / `经营租赁` / 车牌号 | 多行汇总；一票可能多行 |
| 铁路电子客票 | `铁路电子客票` | 票价、乘车日期、开票日期分开；20 位票号 |
| 航空行程单 | `航空运输电子客票行程单` | 票价 + 燃油 + 民航发展基金 |
| 出租车/网约车 | `运输服务` / `客运服务费` / 行程单 | 一页多行程时按行拆分或汇总 |
| 其他 | 以上都不匹配 | 低置信度，人工确认 |

## 去重与拆分

- 优先按发票号码去重（跨批次）。
- 无票号时用文件 SHA-256 兜底；同一文件多页按发票号归组。
- 多页合并 PDF（如 `PDF合并.pdf`）逐页识别；同票号的多页视为一张发票（含清单）。
- 文件名/文件夹名中的金额作为“期望值”参与投票，但不硬覆盖票面。

## 分类

- 默认 9 类：差旅费、餐饮费、汽车费用、福利费、业务招待费、办公费用、广告费用、培训费、其他费用。
- 规则优先级：精确销售方规则 > 项目名称关键词 > 文件名关键词 > 全文兜底。
- 每次人工修正记录到 `rules`；同一修正出现 3 次固化为默认规则。
- 分类结果写 `source`（rule id / manual / fallback），便于追溯。

## 置信度

- `high`：票号 + 金额三重校验 + 日期 + 销售方都命中。
- `medium`：金额正确但缺销售方/票号，或校验有一项不一致。
- `low`：金额或票号缺失、版式未知、扫描件。
- 低置信度默认进入待确认队列，导出前提示数量。

## 实测（2026-10-28，本机真实数据，不入库）

- 780 份 PDF → 1042 条记录（多页 PDF 每页一条），约 20.6 秒。
- 1002 条可识别发票：票号/开票日期/金额/销售方覆盖率均为 100%。
- 33 条扫描件、7 条非发票文档（报销明细、ETC 行程单）被标为待确认。
- 5 个页面含多张发票，已标记“需人工拆分”，尚未自动拆分。
- 人工核对 8 张样本：金额/票号/日期/销售方/分类 8/8；全量 200 张黄金集在 Phase 1b 补。

## 测试与黄金集

- 合成/脱敏 fixture 进仓库；真实发票只在本机 `tests/local/`（gitignore）。
- 每次真实坏例 → 新增 fixture + 回归测试，黄金集只增不减。
- 准确率按字段分开统计，写入 `docs/METRICS.md`。
- 目标：金额 ≥98%、票号 ≥95%、开票日期 ≥98%、销售方 ≥92%、自动分类 ≥85%。

## 边缘情况清单

- 红字发票（负数）：Phase 1a 金额置空并标记“红字/负数发票，金额需人工确认”，不静默当正数
- 折扣行、免税/不征税
- 一页多张发票
- 多页一张发票（清单）
- 票号被空格/换行拆开
- 大写金额与小写不一致
- 扫描件/纯图片（Phase 1 标待确认，Phase 4 可选 OCR）
- 密码区数字被误当金额
- 购买方不是本公司
- 发票日期不在当前批次月份
